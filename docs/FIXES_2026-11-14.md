# แก้ไขจาก Code review / Camera review — 14 พฤศจิกายน 2026

แก้ใน working tree นี้ตามคำสั่งผู้ใช้ ยังไม่ได้ส่ง GitHub หรือติดตั้งบน Pi

## แก้แล้วและตรวจบน Windows

- UI รับผล polling เฉพาะรอบและสถานะการใช้งานเดิม ไม่ให้ผลเก่าทับรอบใหม่หรือการบันทึกที่ใหม่กว่า
- ล็อกช่องผลคน/ผู้ตรวจ/หมายเหตุขณะทำรายการ และตรวจข้อความหลังบันทึก หากเปลี่ยนระหว่างส่งจะคงสถานะยังไม่บันทึกและหยุด finalize/navigation
- CLI เดิมตรวจภาพทุกไฟล์ก่อนโหลดโมเดล ไม่ข้ามไฟล์หาย รองรับนามสกุลตัวใหญ่ และตรวจชื่อคลาส/จำนวนคะแนน/NaN/ช่วงคะแนน/ผลรวมก่อนตัดสิน ผลที่ถูกต้องใช้กฎเดิม
- ภาพสดใช้ camera producer ตัวเดียว เก็บเฉพาะเฟรมล่าสุด ย่อ JPEG เป็น 640×480 quality 75; HTTP อ่าน cache ไม่สั่งถ่ายใหม่ทุก request เป้าหมายอัปเดตสูงสุดประมาณ 10 ครั้ง/วินาที ไม่ใช่ผลวัด FPS บน Pi
- กล้องใช้ preview configuration, main BGR888 1280×960, raw=None, 4 buffers, queue=False, FrameDurationLimits=(66666,66666) และ continuous AF เมื่ออุปกรณ์รองรับ ต้องตรวจความสว่าง/ความชัดหน้างานก่อนใช้งานจริง
- ปุ่มถ่ายรอเฟรมที่เริ่มรับหลังคำสั่งถ่าย บันทึก 1280×960 quality 90 ไม่ใช้ JPEG preview; ปล่อย camera request buffer ก่อนเข้ารหัส และเก็บ metadata/configuration คู่กับภาพ
- งานภาพสดพักเมื่อไม่มีคำขอ ทำให้ไม่เข้ารหัส JPEG ต่อเนื่องระหว่างวิเคราะห์หลังช่วงรอสั้น ๆ
- ยกเลิก timer/fetch และใช้ generation token ป้องกันวงรอบ preview ซ้อนหรือภาพตอบกลับเก่ากลับมาแสดง
- ปุ่มเชื่อมกล้องใหม่ปิดอุปกรณ์เดิมและเปิดใหม่จริง มีเวลารอจำกัดสำหรับเฟรม/worker และปล่อย camera buffer ที่ตอบกลับหลัง timeout; ไม่แสดงภาพเก่าเป็นภาพสดเมื่อกล้อง error
- การรอกล้องไม่ถือ application lock; ตรวจสถานะรอบซ้ำก่อนเพิ่มภาพ ป้องกันเขียนลงรอบที่ถูกวิเคราะห์หรือยืนยันระหว่างรอ
- เพิ่มดาวน์โหลดภาพต้นฉบับจากหน้าดูภาพ, /api/camera/diagnostics, scripts/diagnose-camera.py เพื่อเก็บเวอร์ชัน/config/metadata/hash โค้ด/เวลารับภาพ

## เรื่องกลับขาว–ดำยังต้องตรวจเครื่องจริง

ผู้ใช้ยืนยันว่าเป็นภาพกลับขาว–ดำ แต่ยังไม่ได้ตรวจไฟล์ที่กดถ่าย โค้ดใหม่ใช้ Picamera2.make_image ที่รู้รูปแบบสีแล้วจึงเข้ารหัส JPEG ด้วย Pillow ทั้ง preview และภาพเก็บ ไม่มีการสลับช่องสีหรือกลับสีเพื่อชดเชย การทดสอบภาพขาว/ดำสังเคราะห์ผ่านทั้งสองขนาด แต่ยังยืนยันไม่ได้ว่าแก้อาการที่ Pi แล้ว

หลังเปิดกล้องใน UI ใหม่ ใช้ Python ของ environment UI รัน:

```bash
python scripts/diagnose-camera.py
# ถ้าต้องการแนบภาพที่บันทึก ระบุ session ID เต็มจาก session.json ใน ZIP ส่งออก
python scripts/diagnose-camera.py --session SESSION_ID_32_HEX
```

แทน `python` ด้วย interpreter ของ environment UI จริงหากยังไม่ได้ activate สคริปต์อ่าน HTTP localhost เท่านั้น ไม่เปิดกล้องแย่ง server และไม่เปลี่ยน session สร้างโฟลเดอร์หลักฐานใหม่ใต้ outputs/ (ไม่เขียนทับ) หากเกิด error จะเก็บรายงานบางส่วนพร้อมจบด้วย exit code ไม่ใช่ศูนย์

เปิดภาพ reference-white-black-red-green-blue.png และ JPEG ที่เก็บด้วยโปรแกรมนอกเบราว์เซอร์ ถ้าไฟล์ถูกต้องแต่หน้าเว็บกลับสี ให้ตรวจ forced dark/ส่วนขยาย/accessibility/display ถ้า JPEG กลับสีด้วย ให้เทียบกับ rpicam-hello หลังปิด server และส่ง diagnostics.json พร้อมไฟล์ภาพ สาเหตุสองกลุ่มนี้ยังเป็นสมมติฐาน ไม่ใช่ข้อสรุป

## ชุดส่ง Pi

outputs/field-ui-pi-2026-11-14.zip มี UI/backend/ONNX เดิม/คู่มือ/diagnostic พร้อม bundle-manifest.json ไม่รวมฐานข้อมูล ภาพผู้ใช้ หรือ virtual environment ชุดนี้ไม่รวม legacy PT CLI; การแก้ CLI อยู่ใน workspace inference/ พร้อม input_contract.py

หยุด server เดิมก่อนเปลี่ยนชุด เก็บสำรอง data/field-runtime และใช้โฟลเดอร์โค้ดใหม่ หากต้องเปิดประวัติเดิมให้กำหนด TIRE_DATA_DIR เป็น absolute path ของข้อมูลเดิมที่สำรองแล้วก่อนรัน server อย่าเปิดสอง process บนข้อมูลชุดเดียวกัน ใช้ environment UI ที่ตรวจผ่านเดิมได้โดยไม่อัปเกรดแพ็กเกจโมเดล; เปิดจากโฟลเดอร์โค้ดใหม่ด้วย interpreter UI ที่ทราบ path จริง แล้ว hard reload เบราว์เซอร์

ลำดับตรวจบน Pi: preflight → เปิด/เชื่อมกล้อง → เทียบสี → ถ่าย → วิเคราะห์ → ยืนยัน → เปิดประวัติ → ส่งออก; ทดสอบหยุด/กลับมาดูภาพสดและ reconnect ซ้ำด้วย
